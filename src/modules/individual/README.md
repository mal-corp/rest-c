Разработка и интеграция программного модуля на C++

---

## 1. Цель и задачи

**Цель:** реализовать расчётный модуль, встроить его в готовый REST-сервер и проверить работу (специально есть погрешности в реализации RBAC).

**Задачи:**
1. Изучить готовый сервер: архитектуру, эндпоинты, схему БД.
2. Запустить и протестировать готовые эндпоинты.
3. Разработать словесный алгоритм и блок-схему своего варианта.
4. Реализовать модуль: `parse`, `validate`, `calculate`, `to_json`.
5. Встроить модуль в систему через `task.hpp`.
6. Провести тестирование (пример, границы, ошибки).
7. Оформить отчет и сохранить проект в git.

---

## 2. Исходные данные

**работающий REST-сервер**:

- Эндпойнты (авторизация, расчет, администрирование).
- БД SQLite: `users`, `sessions`, `works`, `logs` в файле `data\rest.db`.
- Демонстрационный модуль статистики (`/works/calc`).
- Каркас индивидуального модуля (`task.hpp`) с примером выполнения работы.

**Технологии:** C++17, SQLite 3, CMake 3.10+, GCC/Clang/MSVC.

**Индивидуальный вариант** содержит: название задачи, входные параметры, ограничения, формулы, контрольный пример.

## 3. Роли и права доступа

### 3.1. Роли

| Роль | Описание |
|------|----------|
| `user` | Обычный пользователь |
| `admin` | Управляет пользователями |
| `owner` | Полные права, включая `admin` |


### 3.3. Матрица доступа

#### Гостевые (без токена)

| Метод | Путь |
|-------|------|
| GET | `/health` |
| GET | `/api/v1.1/counters` |
| GET | `/api/v1.1/history` |
| POST | `/api/v1.1/auth/register` |
| POST | `/api/v1.1/auth/login` |

#### Пользовательские (токен доступа обязателен)

| Метод | Путь | 
|-------|------|
| GET | `/api/v1.1/auth/profile` |
| POST | `/api/v1.1/auth/refresh` |
| POST | `/api/v1.1/auth/logout` |
| PUT | `/api/v1.1/auth/users/password` (себе) |
| POST | `/api/v1.1/works/calc` |
| GET | `/api/v1.1/works/history` |

#### Административные

| Метод | Путь | user | admin | owner |
|-------|------|------|-------|-------|
| GET | `/api/v1.1/auth/users` | ❌ | ✅ | ✅ |
| PUT | `/api/v1.1/auth/users/password` (чужой) | ❌ | ✅* | ✅ |
| DELETE | `/api/v1.1/auth/users` | ❌ | ✅ | ✅ |
| GET | `/api/v1.1/admin/stats` | ❌ | ✅ | ✅ |
| GET | `/api/v1.1/admin/run-tests` | ❌ | ✅ | ✅ |

### 3.4. Особые правила

- Смена **своего** пароля — любой авторизованный.
- Смена **чужого** пароля/удаление УЗ — `admin`: себе и группы `user`, `owner` - всем.
- Пользователя `owner1` удалить нельзя.
- Логи и автотесты — только `admin` / `owner`.

### 3.5. Коды ответов

| Ситуация | Статус |
|----------|--------|
| Успех | 200 / 201 |
| Некорректные данные | 400 |
| Нет токена / просрочен | 401 |
| Нехватка полномочий | 403 |
| Не найдено | 404 |
| Конфликт (дубль) | 409 |
| Ошибка сервера | 500 |

## 4. Индивидуальное задание

### 4.1. Что нужно сделать

1. Изучить шаблон `variant_roi.hpp`.
2. Создать `variant_mine.hpp` на его основе для решения индивидуальной задачи (уточнить у преподавателя).
3. Реализовать:
   - структуры `Input` и `Output`;
   - `parse()` — разбор JSON-тела;
   - `validate()` — проверка ограничений;
   - `calculate()` — расчёт по формулам;
   - `to_json()` — формирование JSON-ответа.
4. В `task.hpp` заменить `#include "variant_roi.hpp"` на `#include "variant_mine.hpp"`.
5. Собрать проект, проверить через веб-интерфейс и curl.

### 4.2. Требования к модулю

| Требование | Значение |
|------------|----------|
| Имя файла | `variant_mine.hpp` |
| Namespace | `TaskVariant` (нельзя менять) |
| Обязательные функции | `parse`, `validate`, `calculate`, `to_json` |
| Обязательные структуры | `Input`, `Output` |
| Зависимости | только стандартная библиотека C++ |

### 4.3. Валидация

Все ограничения варианта проверяются **до расчёта**. При нарушении:

- HTTP-статус `400 Bad Request`.
- Тело — `{"error": "<описание>"}`.

### 4.4. Сохранение результата

Успешный расчёт сохраняется в таблицу `works`:
- `user_id`, `datetime`, `input_json`, `result_json`.
